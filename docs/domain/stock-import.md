# 재고 일괄 입고 (CSV, 기초 재고)

상태: **구현(2026-09-25).** 새 테이블·마이그레이션 없음.

## 목적

처음 도입할 때의 기초 재고나 품목이 많은 입고를, 스프레드시트 한 장으로 받습니다. 모든 입고는 평소처럼 재고 이력(원장)에 남습니다.

## 파일

첫 줄은 열 이름입니다. 이름으로 찾으므로 순서는 상관없습니다.

| 열 | 다른 이름 | 뜻 |
|---|---|---|
| `item_code` | `code` | **필수** |
| `location` | `place` | 비우면 위치 없는 재고 행. 재고 행처럼 **글자 그대로** 비교(대소문자 구분) |
| `lot_no` | `lot` | LOT 관리 품목은 필수, 아니면 비워야 함. 모르는 번호면 새로 등록 |
| `quantity` | `qty` | 0보다 큼. `packs`를 쓰지 않으면 필수 |
| `packs` | `bags`, `purchase_units` | `quantity` 대신: 들어온 [구매 단위](item-details.md) 수(0보다 큼). 수량 = packs × 품목의 구매 단위 크기(소수 4자리 반올림). 품목에 구매 단위가 없거나 `quantity`와 함께 쓰면 줄 오류 |
| `expiry_date` | `expiry` | `yyyy-mm-dd`. 파일이 새로 등록하는 LOT의 유효기한 |

화면의 **Template**으로 헤더만 있는 파일을 받을 수 있습니다.

수량은 소수점에 `.`을 쓰며, 천 단위 쉼표는 세 자리마다 쓸 수 있습니다(예: `1,234.5`). 쉼표가 든 CSV 셀은 따옴표로 감싸야 합니다. `1,2` 같은 잘못된 쉼표 표기는 줄 오류입니다. 저장 정밀도는 소수점 네 자리이며, `packs` 환산 후를 포함해 네 자리 반올림 후 0이 되거나 `numeric(14,4)` 범위를 넘는 수량은 줄 오류입니다.

## API

`POST /inventories/import` — 쓰기 권한

```json
{ "projectId": "...", "dryRun": true, "note": "opening balance", "rows": [{ "itemCode": "SUG-1", "location": "WH-A", "lotNo": "L-1", "quantity": "4", "expiryDate": "2027-01-31" }] }
```

응답: `created`(새 재고 행), `received`(이미 있는 행에 입고), `newLots`, `errors`, `applied`, 줄별 `rows[]`(`action`: create·receive·error).

## 규칙

| # | 규칙 | 이유 |
|---|---|---|
| S1 | 모든 줄을 먼저 검사하고, 한 줄이라도 문제가 있거나 dry run이면 아무것도 받지 않음 | 반쯤 들어간 입고를 찾아 고치는 일이 없게 |
| S2 | 같은 품목·위치·LOT의 재고 행이 있으면 그 행에 **입고(`receipt`)**, 없으면 **새 재고 행**(생성 입고) | 계약서 §4의 "LOT·위치당 한 행" 규칙과 같게 |
| S3 | 기존 행 입고의 참조는 `stock_import` / 가져오기 ID, 메모는 입력한 note(없으면 "Imported stock"). 새 행은 평소 재고 등록과 같음(참조 `inventory`) | 원장에서 한 번의 가져오기를 찾을 수 있게 |
| S4 | 모르는 LOT 번호는 그 품목의 LOT로 먼저 등록(파일 안 여러 줄이 같은 새 번호면 한 번만). 유효기한은 그 번호의 첫 줄 값 | 기초 재고를 LOT 등록 없이 한 번에 |
| S5 | 이미 있는 LOT: 다른 품목의 LOT, 종료·격리된 LOT, 다른 유효기한을 적은 줄은 오류 | 기존 LOT의 정보를 조용히 바꾸지 않게 |
| S6 | 같은 품목·위치·LOT가 파일에 두 번 나오면 오류(합쳐서 한 줄로) | 어느 줄이 맞는지 알 수 없음 |
| S7 | 저장은 LOT 등록, 재고 행 생성(규칙 엔진 `inventory_create` 포함), 재고 명령(`apply`)을 한 트랜잭션에서 부름 | 재고 규칙과 경보가 한 곳에서 돌게 |
| S8 | 한 번에 1000줄까지 | |
| S9 | 파일을 바꾸거나 Cancel하면 이전 파일 읽기·dry run 응답은 화면에 적용하지 않음. 검사 중 취소 가능, 읽기 실패 안내, 실제 Receive 중 파일·메모·취소 잠금 | 다른 파일의 검사 결과로 입고하거나 저장 중 새 입력이 사라지는 것을 방지 |
| S10 | 실제 Receive의 연결 오류·HTTP 500 이상은 저장 미확인. 재제출·파일·메모를 잠그고 이력 확인 안내. Cancel은 화면만 비우고 거래를 취소하지 않음. 업무 400·409는 수정·재시도 허용 | 이 API는 클라이언트 requestId를 받지 않아 같은 파일 재제출도 새 입고. 저장되지 않았다고 단정하거나 안전한 재생을 제공하지 않음 |
| S11 | 같은 필드의 CSV 열은 하나만 허용. quantity·qty, packs·bags, location·place 같은 별칭과 대소문자 중복도 거절 | 뒤쪽 수량·위치가 앞쪽 값을 덮어써 다른 재고로 입고하는 것을 방지 |

## 화면

재고 → Stock 탭 위 **Receive stock from a spreadsheet**(접힘)
- 파일을 고르면 바로 검사해 "N new records, N into existing ones, N new LOTs, N with problems"와 줄별 표를 보여 줍니다.
- 문제가 없으면 **Receive N lines**로 받습니다. note 칸에 적은 말이 기존 행 입고의 메모가 됩니다.
- 받은 뒤 재고·LOT·원장 목록이 새로 고쳐집니다.

### 파일 선택·저장 미확인 회귀 (2026-10-05, §2 2bc–2bd)

- `e2e/stock-import-input.spec.ts` 가짜 API 5건: 오래된 파일 읽기·서버 검사 응답이 최신 검사에 섞이는 2건, 검사 중 취소 불가, 파일 읽기 실패 누락, 실제 입고 중 입력 미잠금까지 수정 전 5건 실패. 수정 후 최신 파일 9만 한 번 입고·취소한 파일 무시·읽기 재시도·저장 중 잠금 검증.
- `e2e/stock-import-unconfirmed.spec.ts` 3건: 9를 입고한 뒤 연결 오류·503 응답 유실 2건과 거래 없는 409. 미확인 재제출 차단·이력 확인 안내·Cancel의 거래 불변, 업무 거절 뒤 정상 재시도 검증. 수정 전 유실 2건 안내·차단 누락.
- 두 스펙 8건, 전체 프런트 449건·타입 검사·린트·빌드 통과. 서버·DB·마이그레이션 변경 없음. 백엔드 마지막 전체 검증은 2as의 1,023건·라인 81.02%; 이번 프런트 수정 뒤 서버 테스트는 다시 실행하지 않았습니다.
- **현재 한계:** 취소·페이지 이동·새로고침 뒤 미확인 입고 상태를 영구 복원하지 않습니다. 이력 확인 후 새 파일 선택은 새 거래입니다. 서버가 만든 `stock_import` ID는 요청마다 새 값이므로, CSV 입고의 멱등 재생은 아직 구현되지 않았습니다.
