# C4. 권한 매트릭스 초안

**한 줄 결론:** 프로젝트 멤버십을 먼저 확인하고, 쓰기는 editor 이상, 승인·멤버 관리는 owner로 제한하는 현재 코드를 기준으로 정리했다.

## 한 것 / 못 한 것

- `ProjectAccessService`의 read/write/owner 검사와 workflow·project API 및 기존 권한 통합 테스트의 범위를 읽었다. 표는 대표 경로의 현재 코드 기준 초안이다. 모든 엔드포인트의 자동 권한 시험과 시스템 관리자 우회 정책 검증은 하지 않았다.

| API/작업 | 비회원 | viewer | editor | owner | 시스템 관리자 |
|---|---|---|---|---|---|
| 프로젝트·workflow·canvas 조회 | 403 | 허용 | 허용 | 허용 | 관리 API 별도; 일반 API는 멤버십 필요 |
| workflow·node·connection 쓰기 | 403 | 403 | 허용 | 허용 | 일반 API는 멤버십 필요 |
| STOMP presence/구독 | 403 | 허용 | 허용 | 허용 | 일반 API는 멤버십 필요 |
| STOMP node move | 403 | 403 | 허용 | 허용 | 일반 API는 멤버십 필요 |
| BOM 제출·재고 거래·생산 실행 | 403 | 403 | 허용 | 허용 | 일반 API는 멤버십 필요 |
| BOM 승인·반려·폐기, 작업지시 승인/취소 | 403 | 403 | 403 | 허용 | 일반 API는 멤버십 필요 |
| 프로젝트 멤버 역할 변경·제거 | 403 | 403 | 403 | 허용 | 일반 API는 멤버십 필요 |
| `/admin/projects` | 관리자 권한 필요 | 관리자 권한 필요 | 관리자 권한 필요 | 관리자 권한 필요 | 허용 |

초대 수락·로그인·공개 URL과 소유 프로젝트 예외는 위 표의 멤버십 API와 별개다. 실서비스 정책으로 확정하기 전에 모든 경로를 권한 테스트와 대조해야 한다.

## 사람 결정이 필요한 것

- D3: 관리자 우회 여부와 owner 전용 승인/멤버 조작 범위를 확정한다.

## 다른 담당에게 넘길 것

- **권한/보안 담당:** 승인 뒤 모든 API·STOMP destination에 대한 역할별 통합 테스트를 보강한다.
