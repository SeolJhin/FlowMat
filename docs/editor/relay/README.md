# FlowMat Editor Relay

FlowMat 에디터 작업을 시간대가 다른 작업자끼리 안전하게 이어가기 위한 바통 터치 규칙이다.

이 문서는 작업 과정의 대화 기록을 쌓는 곳이 아니다. 다음 작업자가 현재 상태를 빠르게 확인하고, 같은 조사나 실수를 반복하지 않도록 **커밋·검증·결정·다음 행동**을 남기는 것이 목적이다.

## 시작 지점

에디터 작업을 시작할 때는 다음 순서로 읽는다.

1. [`../current-state.md`](../current-state.md): 장기 구조와 완료된 기준선
2. [`BATON.md`](./BATON.md): 지금 이어서 할 작업
3. `BATON.md`가 연결한 `history` 문서: 직전 작업의 상세 근거

## 문서 구조

```text
docs/editor/relay/
├─ README.md
├─ BATON.md
├─ TEMPLATE.md
└─ history/
   └─ YYYY-MM/
      └─ YYYY-MM-DD-HHmm-author-topic.md
```

- `README.md`: 릴레이 운영 규칙
- `BATON.md`: 현재 상태와 다음 행동만 담는 최신 바통
- `TEMPLATE.md`: 상세 기록을 작성할 때 복사하는 양식
- `history`: 교대별 상세 기록. 인계 후에는 원칙적으로 수정하지 않는다.

## 교대 절차

### 작업 시작

1. `BATON.md`의 branch와 head commit이 로컬 Git 상태와 맞는지 확인한다.
2. 최신 상세 기록의 완료 작업, 미검증 항목, 다음 행동을 읽는다.
3. 직전 커밋을 검토하고 문제를 발견하면 자신의 새 기록 또는 Draft PR에 피드백을 남긴다.
4. 원격 변경이 있다면 작업 전에 동기화한다. 공유 브랜치에서는 강제 push를 하지 않는다.

### 작업 종료

1. 코드 변경을 기능 단위로 커밋한다.
2. 실행한 검증 명령과 결과를 기록한다. 실행하지 않은 검증은 별도로 명시한다.
3. `TEMPLATE.md`를 복사해 `history/YYYY-MM/` 아래에 상세 기록을 작성한다.
4. `BATON.md`를 새 상세 기록, 최신 commit, 다음 작업 1~3개로 갱신한다.
5. 릴레이 문서는 코드 변경과 구분되는 문서 커밋으로 남긴다.
6. 다음 작업자가 받을 수 있도록 브랜치를 push한다.

완성되지 않은 작업을 넘겨야 한다면 로컬 stash에만 두지 않는다. `main`이 아닌 공유 feature branch에 WIP 커밋으로 올리고, 불완전한 부분과 되돌리는 방법을 상세 기록에 적는다.

## 기록 이름

```text
YYYY-MM-DD-HHmm-author-topic.md
```

- 시간은 `Asia/Seoul`(KST) 기준 24시간제로 쓴다.
- `author`는 Git 사용자 이름이나 팀에서 합의한 영문 ID를 쓴다.
- `topic`은 `connectors`, `ribbon`, `persistence`처럼 짧은 kebab-case를 쓴다.

예시:

```text
2026-08-14-1100-seoly-connectors.md
2026-08-14-1800-rjw04-ribbon-review.md
```

## 기록 원칙

- 확인된 사실과 추측을 구분한다.
- `테스트 완료`라고만 쓰지 않고 실행한 명령과 성공·실패 결과를 적는다.
- 브라우저 수동 검증은 경로, 조작, 기대 결과, 실제 결과를 적는다.
- 작업하지 않은 범위와 의도적으로 제외한 범위를 적는다.
- 다음 작업은 첫 행동이 명확한 동사형 문장으로 쓴다.
- 작업 트리가 dirty라면 미커밋 파일과 그 소유자를 적는다.
- 코드 줄별 피드백은 가능하면 Draft PR 리뷰에 남기고, 바통에는 결론과 링크만 남긴다.
- 지난 `history` 기록은 덮어쓰지 않는다. 정정이 필요하면 새 기록에서 이전 문서를 링크한다.
- 비밀번호, 토큰, 개인정보, 내부 접속 정보와 개인 PC의 절대 경로를 기록하지 않는다.

## 문서별 책임 범위

| 문서 | 담아야 할 내용 | 담지 않을 내용 |
|---|---|---|
| `current-state.md` | 완료된 구조, 장기 기준선 | 매 교대의 세부 로그 |
| `BATON.md` | 최신 commit, 현재 상태, 다음 작업 | 긴 조사 과정과 과거 기록 |
| `history/*.md` | 한 교대의 변경·검증·결정 근거 | 계속 바뀌는 현재 상태 |
| ADR | 되돌리기 어려운 구조적 결정 | 단순 구현 진행 상황 |
| Draft PR | 코드 줄별 검토와 토론 | 장기 프로젝트 상태 요약 |

## 권장 커밋 메시지

```text
docs(relay): pass editor baton for 2026-08-14
```

## 인계 완료 확인

- [ ] `BATON.md`가 가장 최근 상세 기록을 가리킨다.
- [ ] branch와 head commit이 실제 Git 상태와 일치한다.
- [ ] 실행한 검증과 미실행 검증이 구분되어 있다.
- [ ] 다음 작업이 1~3개로 우선순위화되어 있다.
- [ ] blocker가 있다면 해제에 필요한 사람·결정·환경이 적혀 있다.
- [ ] 비밀 정보나 개인 PC 절대 경로가 없다.
